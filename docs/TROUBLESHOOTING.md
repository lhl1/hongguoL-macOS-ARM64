# 遇到问题时，先看是哪一步

[← 返回首页](../README.md) · [安装说明](INSTALL_MACOS.md)

| 表现 | 优先检查 |
| --- | --- |
| 下载后说“已损坏”或无法打开 | 有没有解压完整目录并运行准备脚本，而不是直接打开源 `.app` |
| 准备时 Killed: 9 | 终端给出的失败阶段、签名/隔离状态；不能直接判断是视频接口故障 |
| 搜索正常，所有视频失败 | 设置导出的 source/decoder 状态与字节数、本机视频自检 |
| M102 | 视频源读取失败这一类，需结合状态和阶段，不等同特定证书问题 |
| 游客编号无效 | 服务是否接受新游客注册、网络是否可用；不复制别人编号或伪造身份 |
| 钥匙串提示 | 是否主动实验登录；游客启动不应需要读取旧账号 |
| 某部剧不能播 | 预约、锁集、授权、视频模型过期及服务状态，不能绕过原状态 |
| 筛选没有内容 | 服务返回、体裁/条件和分页上下文，不能用别的页面结果冒充 |

## 应用打不开

运行随包 `诊断Mac启动.command`。准备失败日志在终端指明的 `~/Library/Logs/Hongguo/Install-…/`。保留完整目录与原校验清单，不要独自替换 FFmpeg，也不要关闭全局 Gatekeeper/SIP。

## 应用打开但视频失败

先运行 `验证Mac视频.command`，它只检查合成媒体链路。通过后再运行 `验证Mac版.command`，验证新游客和真实服务。两者有不同目的：合成首帧通过不保证远端服务可用。

在设置导出日志。日志保留固定错误类别、HTTP 状态、阶段、字节数、版本和系统信息，不保留真实播放 URL/密钥。原始子进程 stderr 不作为公开排查附件。

## 提交 issue 的建议格式

```text
版本：
Mac 芯片 / macOS 版本：
发生在安装还是播放：
复现步骤：
期望发生什么：
实际出现什么错误 / 固定错误码：
本机视频自检是否通过：
脱敏日志是否可提供：
```

发出日志前再自行检查。不要附手机号、验证码、系统密码、Cookie、会话 token、设备 ID、完整请求签名、播放地址/密钥或未审查截图。不要把拒绝登录说成已经登录，别把本地观看记录当作云端记录。
